📘 HOJA DE RUTA DEL PRODUCTO
Kalido-Lite + TAISA (Plataforma Productiva)
🔹 PUNTO 0 – Definición del producto, alcance y principios
🎯 Objetivo

Definir formalmente qué es el producto, qué problema resuelve, qué NO resuelve y bajo qué principios se construye, para evitar desvíos, sobre-ingeniería y dependencias innecesarias durante el desarrollo.

Este punto es obligatorio antes de escribir código productivo.

0.1 Definición del producto

Kalido-Lite + TAISA es una plataforma de gobierno técnico del EDW que permite:

Capturar estados estructurales de plataformas de datos

Detectar y versionar cambios técnicos

Calcular lineage e impacto de forma reproducible

Evaluar riesgos y sugerir acciones mediante IA explicable

Proveer trazabilidad completa de decisiones técnicas

0.2 Problema que resuelve

El producto resuelve:

Falta de visibilidad ante cambios estructurales

Riesgo no controlado en evoluciones del EDW

Dependencia de herramientas comerciales opacas

Falta de explicabilidad en decisiones técnicas

Alto costo de gobierno de datos

0.3 Problemas que NO resuelve (fuera de alcance)

El producto NO busca:

Reemplazar herramientas BI

Ejecutar ETL

Diseñar modelos de negocio

Reemplazar data catalog funcional

Administrar permisos de usuarios finales

0.4 Público objetivo

Usuarios principales:

DBAs

Arquitectos de datos

Data Engineers

Equipos de plataforma

Usuarios secundarios:

Gobierno de datos

Auditores técnicos

Líderes de tecnología

0.5 Principios de diseño del producto

El producto se rige por los siguientes principios:

Estado primero: todo se guarda, nada se infiere sin contexto

Explicabilidad obligatoria: ninguna decisión es una caja negra

Desacople total: motores, IA y UI independientes

Motor interno propio: sin dependencia del EDW productivo

Extensible por diseño: nuevos motores, reglas y razonamientos

Costo controlado: evitar licencias y lock-in

0.6 Arquitectura conceptual del producto

Componentes formales del producto:

Motor interno de metadata (PostgreSQL)

Capa de abstracción de metadata (templates + adaptadores)

Motor de snapshots

Motor de diff

Motor de grafo (lineage + impacto)

Motor de razonamiento (TAISA)

API de orquestación

UI operativa

0.7 Modelo de evolución del producto

El producto se desarrolla de forma:

Incremental

Versionada

Backward compatible

Auditable

Cada módulo puede evolucionar sin romper los demás.

4.1 Principios de diseño del modelo de datos

El modelo de datos cumple los siguientes principios:

Estado inmutable una vez versionado

Identificadores internos (surrogate keys)

🔹 PUNTO 5 – Flujo operativo del producto (end-to-end)
🎯 Objetivo

Definir el flujo operativo completo del producto, desde la captura de metadata hasta la decisión técnica final, describiendo qué ocurre, en qué orden y qué artefactos se generan en cada etapa.

Este punto describe cómo se usa el producto en la práctica, independientemente de la tecnología.

5.1 Principios del flujo operativo

El flujo operativo del producto se rige por:

Ejecución explícita y controlada

Estados y eventos persistidos

Reproducibilidad total

Separación entre detección, análisis y decisión

Intervención humana como paso final

5.2 Disparadores del flujo

El flujo puede iniciarse por:

Ejecución manual (DBA / Arquitecto)

Ejecución programada

Ejecución por evento externo (MVP+)

Ejecución ad-hoc para análisis puntual

Todos los disparadores generan nuevos eventos, nunca sobrescriben estados.

5.3 Etapas del flujo operativo
5.3.1 Captura de metadata

Se ejecutan templates de metadata

Se obtiene metadata estructural normalizada

No se persiste aún

Artefacto generado:
Metadata temporal normalizada

5.3.2 Creación de snapshot

Se crea un nuevo snapshot

Se persiste el estado completo

El snapshot es inmutable

Artefacto generado:
snapshot

5.3.3 Detección de cambios

Se seleccionan dos snapshots

Se comparan estructuras

Se generan eventos de cambio

Artefactos generados:
change_event

5.3.4 Construcción de grafo técnico

Se construye o actualiza el grafo

Se versiona por snapshot

Se preparan relaciones para impacto

Artefactos generados:
graph_node, graph_edge

5.3.5 Análisis de impacto

Se evalúa cada cambio

Se identifican objetos impactados

Se calcula profundidad y tipo de impacto

Artefactos generados:
impact_event

5.3.6 Razonamiento inteligente (TAISA)

Se envía contexto a TAISA

Se interpreta el cambio y su impacto

Se evalúa riesgo

Se generan recomendaciones

Se produce explicación humana

Artefactos generados:
reasoning_event

5.3.7 Visualización y decisión humana

El usuario visualiza:

Cambio

Impacto

Riesgo

Explicación

Se toma decisión técnica informada

Resultado:
Decisión humana respaldada por evidencia

5.4 Flujo operativo resumido
Metadata Capture
      ↓
Snapshot Creation
      ↓
Change Detection
      ↓
Graph Construction
      ↓
Impact Analysis
      ↓
TAISA Reasoning
      ↓

5.5 Manejo de re-ejecuciones

Cada etapa puede re-ejecutarse

No se destruye información previa

Se mantiene trazabilidad completa

Se pueden comparar ejecuciones

5.6 Estados del flujo

Cada ejecución puede estar en uno de los siguientes estados:

CREATED

SNAPSHOT_COMPLETED

DIFF_COMPLETED

IMPACT_COMPLETED

REASONING_COMPLETED

FAILED

5.7 Errores y recuperación

Errores técnicos no invalidan snapshots previos

Errores de TAISA permiten reintentos

El sistema nunca queda en estado inconsistente

5.8 Relación con auditoría y gobierno

El flujo garantiza:

Evidencia persistida

Trazabilidad completa

Justificación de decisiones

Reproducibilidad histórica

🔹 PUNTO 7 – Integración con TAISA (arquitectura cognitiva del producto)
🎯 Objetivo

Definir cómo TAISA se integra como motor cognitivo del producto, estableciendo responsabilidades claras, límites estrictos y un flujo de razonamiento explicable, auditable y desacoplado.

Este punto asegura que la inteligencia potencie al producto sin convertirlo en una caja negra.

7.1 Rol de TAISA dentro del producto

TAISA actúa como:

Motor de razonamiento técnico

Evaluador de riesgo estructural

Generador de recomendaciones

Explicador de impacto y decisiones

TAISA no es:

Un sistema de persistencia

Un orquestador

Un ejecutor de cambios

Un reemplazo del criterio humano

7.2 Principios de integración cognitiva

La integración con TAISA se rige por:

Stateless by design: TAISA no guarda estado interno

Context-driven: razona solo con lo que recibe

Explain-first: toda salida debe ser explicable

Human-in-the-loop: la decisión final es humana

No vendor lock-in: TAISA es intercambiable

7.3 Información enviada a TAISA

TAISA recibe contexto estructurado, nunca acceso directo a bases de datos.

Contexto típico:

Evento de cambio

Objetos impactados

Tipo y profundidad de impacto

Metadata relevante

Historial de cambios (resumido)

Políticas técnicas (si aplica)

Formato:

JSON estructurado

Versionado

Validado

7.4 Procesos cognitivos realizados por TAISA

TAISA realiza:

Clasificación del cambio

Evaluación del riesgo técnico

Identificación de escenarios posibles

Generación de recomendaciones

Producción de explicación humana

Cada proceso es determinístico a nivel de entrada, aunque el razonamiento sea flexible.

7.5 Salida de TAISA

TAISA devuelve:

Clasificación del cambio

Nivel de riesgo (ej. bajo / medio / alto)

Recomendaciones técnicas

Explicación textual

Indicadores de confianza

Toda salida:

Es persistida

Es versionada

Es auditable

7.6 Persistencia del razonamiento

El producto:

Guarda todas las respuestas de TAISA

Asocia razonamiento a eventos de cambio

Permite análisis histórico

Permite comparar razonamientos entre versiones

TAISA no recuerda; el producto sí.

7.7 Aprendizaje del sistema (indirecto)

El aprendizaje ocurre por:

Comparación entre recomendaciones y decisiones humanas

Análisis histórico de resultados

Ajuste de políticas y prompts

Evolución del modelo de razonamiento

Este aprendizaje no es automático destructivo.

7.8 Versionado de TAISA

El producto registra:

Versión de TAISA

Versión del prompt

Parámetros cognitivos

Fecha de ejecución

Esto garantiza:

Reproducibilidad

Auditoría

Comparabilidad histórica

7.9 Modo degradado

Si TAISA:

No responde

Está deshabilitada

Falla

El producto:

Continúa funcionando

Muestra análisis técnico básico

Informa la falta de razonamiento IA

7.10 Seguridad y confidencialidad

TAISA no accede a datos sensibles

No se envían credenciales

No se envían datos de negocio

Cumple modo privado / aislado

✅ Resultado esperado del Punto 7

Integración cognitiva clara y segura

Inteligencia explicable y controlada

Base sólida para evolución futura

Diferenciación real frente a herramientas tradicionales
